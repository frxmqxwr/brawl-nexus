# BRAWL // NEXUS — MAP INTELLIGENCE / массовая статистика

Дата реализации: 2026-11-21

## Что работает сразу после публикации
- Секция **Карты / Meta** (\`#maps\`), фильтры по режиму, названию, текущей ротации, архивным картам.
- Карточка карты: игровая PNG-миниатюра, режим, статус ротации.
- Своя статистика игрока по данной карте из локально накопленных журналов Supercell.
- Подбор по реальным мета-данным, если пришли из D1/провайдера: WR / use rate / количество боёв, команды, прямые контры.
- Переход к драфту с уже выбранной картой.
- В Quintillion (Heist) — **архивный срез**, вручную предоставленный в обсуждении пользователем, с пометкой «не LIVE». Он не экстраполируется на другие карты.

## Как получить большую собственную базу игр (Cloudflare D1)
**Это дополнительная настройка**, а не автоматический результат GitHub коммита.

### 1. Создай D1
В Cloudflare Dashboard → Storage & Databases → D1 → Create database:
\`brawl-nexus-meta\`.
Сохрани выданный \`database_id\`.

### 2. Применение схемы
Один раз выполни SQL из \`database/001_meta.sql\` в D1 Console (или локально):
\`\`\`bash
npx wrangler d1 execute brawl-nexus-meta --remote --file database/001_meta.sql
\`\`\`
Если команда выполняется из папки \`workers/meta-collector\`, путь к файлу надо скорректировать на \`../../database/001_meta.sql\`.
Схема содержит \`meta_matches\`, \`meta_picks\` и \`meta_crawl_queue\`.

### 3. Привяжи D1 к Pages
Cloudflare → Workers & Pages → **Pages: brawl-nexus** → Settings → Bindings → Add → D1 database:
- Variable name (binding): \`META_DB\`
- Database: \`brawl-nexus-meta\`
- Environment: **Production** (при необходимости и Preview)

**Важно:** переменные \`BRAWL_API_TOKEN\` и \`BRAWL_API_BASE_URL\` должны быть сохранены в **Production Variables and Secrets**, а сам \`BRAWL_API_TOKEN\` — только как Secret. Код не содержит ключей. Выполни новый Production deploy.

После этого при каждом успешном запросе \`/api/player/{tag}/log\` Cloudflare будет сохранять подтверждённые матчи в D1 в фоновом контексте. Дубликаты фильтруются по идентификатору матча и составу.

### 4. Автоматический сборщик (отдельный Worker)
Для автоматического сбора матчей, даже если люди не заходят на сайт:
- Открой \`workers/meta-collector/wrangler.toml\`.
- Замени \`REPLACE_WITH_YOUR_D1_DATABASE_ID\` на реальный \`database_id\`.
- В корне репозитория выполни:
\`\`\`bash
cd workers/meta-collector
npx wrangler deploy
npx wrangler secret put BRAWL_API_TOKEN
\`\`\`
- В **Worker → Settings → Variables and Secrets** добавь обычную переменную \`BRAWL_API_BASE_URL\` с адресом рабочего Supercell API/proxy, если используется иной адрес.
- Привязка \`META_DB\` автоматически возьмётся из wrangler.toml при деплое.

Worker запускается **ежечасно**, берёт публичный топ игроков из \`/rankings/global/players\` и до 8 профилей из очереди, читает **их последние 25** боёв, добавляет участников матчей в очередь и сохраняет только уникальные проверенные двухкомандные матчи. Собираются: карта, режим, известный исход, составы, бойцы, кубки участников и время матча. При временной ошибке игрок повторно ставится в очередь. Никакие аккаунты не взламываются, игрокам уведомлений не отправляется.

### 5. Проверка
- \`https://brawl-nexus.pages.dev/api/meta-status\` — наличие D1 и текущая величина собственной выборки.
- \`https://brawl-nexus.pages.dev/api/map-intel?map=Quintillion&mapId=15001170&mode=heist&band=all\` — агрегат для конкретной карты.
- На странице \`#maps\` статистика появится по мере поступления матчей.

Данные из D1 выводятся при наличии **от 20 матчей по карте/фильтру**, а связанные команды — от 5 записанных игр, прямые матчапы — от 10. Массовая выборка зависит от времени работы сборщика, Supercell API, лимитов Cloudflare, состава посещаемых игроков и доступности карт.

## Методика
Винрейт бойца: \`победы с бойцом / все исходы матчей с бойцом\` среди **только тех матчей, которые удалось собрать**. Ничьи и неизвестные исходы не входят.

Частота выбора: \`количество зафиксированных появлений бойца / количество слотов участников во всех матчах выборки\`. Для команд 3×3 это шесть слотов на игру; показатель не тождественен вероятности присутствия хотя бы в одной из двух команд.

Пары: два бойца из **одной** команды в **одном** матче; трио: три бойца в одной команде; контрпики: соперники из **разных** команд в одном матче. Проценты не считаются из отдельных независимых матчей. По малым выборкам ограничиваем публикацию.

База ориентирована на наблюдаемую публичную выборку, **не на все матчи игроков мира**. Одна команда учитывается дважды (по одному разу для каждого из двух игроков), а матч — один раз по уникальному идентификатору. У игрового API нет полных pick/ban-фаз Ranked: система не утверждает, что знает реальные баны и порядок выбора.

## Другие источники
- BrawlAPI (\`https://brawlapi.com/\`) — статический каталог и изображения, **без** актуальных глобальных винрейтов.
- Brawlify, Brawl Planet, Brawl Time Ninja — самостоятельные аналитические платформы. Их закрытые базы данных и платные функции не копируются и не скачиваются.
- \`MAP_STATS_FEED_URL\` — ранее поддерживаемый в NEXUS пользовательский HTTPS-источник статистики, если его оператор разрешает интеграцию. NEXUS его не включает без настройки. Контракт: JSON с полем \`stats: [{brawlerId,name,winRate,sampleSize}]\`; дополнительно \`sample\`, \`updatedAt\`, \`teams\`, \`pairs\`, \`counters\`.

## Масштабирование
При миллионах матчей нужно перенести тяжёлые join-агрегаты в отдельные ежечасно вычисляемые таблицы и добавить кэш Cloudflare Cache API/KV. Сейчас запрос карты ограничивает выход десятками записей, но при бесконтрольном росте БД тяжёлые аналитические JOIN-запросы могут превысить лимиты бесплатного D1.

## Ограничения и безопасность
- Не размещай секреты в репозитории, чате, веб-клиенте.
- Сторонний прокси получает заголовок Bearer; используй только доверенный или собственный сервер с фиксированным исходящим IP.
- Служебные \`/api/meta-status\` и \`/api/map-intel\` отдают только агрегаты, а не список тегов игроков.
- Пока D1, Worker и API не настроены в Cloudflare, массовая база **не запускается**, а сайт показывает каталог, доступные личные бои и явно обозначенные архивные данные.
